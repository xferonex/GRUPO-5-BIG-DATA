Sección 1 – Big Data, Hadoop, Hive y Apache Spark

En esta sección analizamos un caso real de aplicación del Big Data, comparamos distintas soluciones del ecosistema Hadoop, estudiamos las diferencias entre MySQL y HiveSQL y evaluamos el uso de Apache Spark y MapReduce.

1. Big Data: caso real de Netflix

Presentación y justificación de la organización elegida

Netflix es una plataforma de streaming muy conocida que permite ver películas, series y documentales a través de Internet. Actualmente cuenta con usuarios de muchos países y maneja una gran cantidad de información relacionada con el uso de su plataforma.

Hemos elegido Netflix para este trabajo porque creemos que es un buen ejemplo de cómo una empresa utiliza el Big Data en su día a día. Cada vez que un usuario busca una película, empieza a ver una serie, pausa un vídeo o deja de verlo, se pueden generar datos que ayudan a conocer mejor sus gustos y preferencias.

Un ejemplo bastante claro es el sistema de recomendaciones de Netflix. Cuando entramos en la plataforma, no todos vemos las mismas sugerencias, ya que Netflix analiza nuestros hábitos de visualización para recomendarnos contenidos que nos puedan interesar.

Por todo esto, pensamos que Netflix es una buena organización para analizar las cinco V del Big Data, porque trabaja con muchos datos diferentes, que se generan constantemente y que deben procesarse correctamente para poder sacarles utilidad.

1.a. Las cinco V del Big Data

Netflix genera y utiliza una gran cantidad de información cada día. Para entender mejor cómo aplica el Big Data, vamos a explicar las cinco V y relacionarlas con ejemplos concretos de su plataforma.

Las 5 V ¿En qué consiste? Ejemplo aplicado a Netflix
Volumen El volumen hace referencia a la cantidad de datos que una empresa genera, recibe y necesita almacenar. En Big Data, estas cantidades pueden ser tan grandes que resulta complicado gestionarlas con herramientas tradicionales. Por eso se utilizan sistemas que permiten almacenar y procesar información repartiendo el trabajo entre varios servidores. Netflix tiene millones de usuarios repartidos por diferentes países. Cada vez que alguien reproduce una película, busca una serie, añade un título a su lista o termina un capítulo, puede generar información sobre su actividad. Al juntar estos registros durante meses o años, se obtiene una cantidad enorme de datos que Netflix necesita gestionar.
Velocidad La velocidad se refiere a la rapidez con la que se generan, reciben y procesan los datos. En algunas empresas la información llega continuamente y es necesario analizarla casi al momento. No siempre es suficiente guardar los datos para estudiarlos al día siguiente, porque algunas decisiones necesitan tomarse rápidamente. En Netflix hay usuarios viendo contenidos a todas horas. Mientras utilizan la plataforma, se pueden registrar acciones como iniciar una reproducción, pausarla, avanzar escenas o cambiar de película. Parte de esta información puede analizarse rápidamente para detectar problemas de reproducción o mejorar el funcionamiento del servicio.
Variedad La variedad significa que los datos no son todos iguales ni tienen el mismo formato. Podemos encontrar datos estructurados, como tablas; semiestructurados, como archivos JSON; y no estructurados, como textos, imágenes o vídeos. Una plataforma Big Data debe poder trabajar con estos diferentes tipos de información. Netflix utiliza historiales de visualización, búsquedas, información de dispositivos, idiomas seleccionados, características de películas y registros técnicos. Por ejemplo, no tiene el mismo formato una fecha de reproducción que la descripción de una serie o un registro de errores. Todos pueden aportar información útil.
Veracidad La veracidad está relacionada con la calidad, precisión y fiabilidad de los datos. Tener mucha información no significa que toda sea correcta. Puede haber registros incompletos, errores, datos duplicados o situaciones que provoquen interpretaciones equivocadas. Por eso es importante revisar la información antes de utilizarla. Imaginemos que un usuario empieza una película y la abandona a los dos minutos. Eso no significa necesariamente que no le haya gustado: puede haberla abierto por error. También puede ocurrir que varias personas compartan un perfil. Netflix debe tener en cuenta estas situaciones para evitar conclusiones equivocadas sobre los gustos.
Valor El valor consiste en conseguir que los datos sirvan para algo útil. Una empresa puede almacenar millones de registros, pero si no los analiza, esa información aporta poco. El objetivo del Big Data es transformar los datos en conocimiento para mejorar servicios, conocer a los clientes y tomar mejores decisiones. Un ejemplo es el sistema de recomendaciones de Netflix. La plataforma analiza información sobre los contenidos que ven los usuarios para sugerir películas y series que podrían interesarles. También puede estudiar qué contenidos tienen más aceptación y utilizar esa información para mejorar su catálogo y servicio.

1.b. Orden de criticidad de las cinco V

Aunque las cinco V del Big Data son importantes, no todas tienen la misma criticidad para una empresa como Netflix. Hemos decidido ordenarlas teniendo en cuenta la cantidad de información que genera la plataforma, la rapidez con la que necesita procesarla y cómo utiliza esos datos para mejorar su servicio.

Posición V del Big Data Justificación aplicada a Netflix
1.º Velocidad Consideramos que es la más crítica porque Netflix recibe continuamente información de usuarios que reproducen contenidos en diferentes partes del mundo. Algunos datos, como los relacionados con errores o problemas de reproducción, necesitan analizarse rápidamente. Si la plataforma tarda demasiado en detectar estos problemas, la experiencia de los usuarios puede verse afectada.
2.º Volumen Netflix genera y almacena una cantidad enorme de información relacionada con reproducciones, búsquedas, dispositivos y hábitos de visualización. Esta cantidad de datos hace necesario disponer de sistemas que puedan ampliar su capacidad de almacenamiento y procesamiento conforme aumenta el número de usuarios.
3.º Valor Los datos tienen que servir para obtener algún beneficio. Netflix puede utilizarlos para personalizar recomendaciones, conocer mejor los gustos de los usuarios y tomar decisiones sobre los contenidos de su catálogo. Aunque es muy importante para el negocio, primero debe ser capaz de recoger y procesar correctamente la información.
4.º Veracidad Es importante que los datos sean fiables para no sacar conclusiones equivocadas. Por ejemplo, que un usuario abandone una película no significa necesariamente que no le guste. Si Netflix interpreta mal estos datos, sus recomendaciones pueden ser menos acertadas.
5.º Variedad Netflix trabaja con distintos tipos de información, como historiales, búsquedas, datos técnicos y características de los contenidos. Aunque necesita herramientas capaces de gestionar estos formatos, consideramos que en este caso supone un reto técnico menor que procesar rápidamente grandes cantidades de datos.

¿Qué V condiciona más el diseño técnico de Netflix?

En nuestro análisis, consideramos que la velocidad es la V que más condiciona el diseño técnico de Netflix.

Esto se debe a que Netflix tiene usuarios conectados continuamente desde diferentes países y dispositivos. Mientras utilizan el servicio, se generan eventos relacionados con las reproducciones, las búsquedas y el funcionamiento de la aplicación.

Para gestionar esta información, Netflix necesita una infraestructura capaz de recibir muchos eventos al mismo tiempo y procesar rápidamente aquellos que requieren una respuesta inmediata.

Por ejemplo, si se producen errores de reproducción en una determinada zona, es importante detectarlos cuanto antes para investigar el problema y reducir su impacto.

Por este motivo, la plataforma necesita sistemas distribuidos que permitan repartir el procesamiento entre diferentes servidores y aumentar su capacidad cuando sea necesario.

En conclusión, hemos situado la velocidad en primera posición porque condiciona cómo se reciben y procesan los datos. El volumen ocupa el segundo lugar porque también obliga a utilizar una infraestructura escalable, capaz de trabajar con grandes cantidades de información.

Este orden es nuestra valoración del caso de Netflix. No todos los datos necesitan procesarse en tiempo real: algunos análisis pueden realizarse posteriormente por lotes.

1.c. Herramientas del ecosistema Hadoop

En el apartado anterior hemos considerado que las dos V más críticas para Netflix son la velocidad y el volumen. Para gestionar estas necesidades, podemos utilizar diferentes herramientas del ecosistema Hadoop y otras tecnologías complementarias, que permiten trabajar con grandes cantidades de información repartiendo el almacenamiento y el procesamiento entre varios servidores.

1. Velocidad: YARN, Apache Spark y Apache Kafka

La velocidad es importante porque Netflix recibe continuamente información de sus usuarios, como las reproducciones, las búsquedas o las pausas de los vídeos.

Dentro del ecosistema Hadoop encontramos YARN, una herramienta que se encarga de gestionar los recursos de los servidores y organizar la ejecución de las aplicaciones. Esto permite repartir el trabajo entre diferentes máquinas y aprovechar mejor los recursos disponibles.

Para procesar los datos rápidamente, también podríamos utilizar Apache Spark, especialmente Spark Structured Streaming, que permite analizar grandes cantidades de información conforme se van recibiendo.

Otra herramienta complementaria es Apache Kafka, que permite recoger y distribuir los eventos que se generan continuamente en la plataforma.

Por ejemplo, si muchos usuarios empiezan a tener problemas al reproducir una película, Kafka podría recoger los eventos relacionados con esos errores y Spark analizarlos rápidamente para ayudar a detectar el problema.

De esta manera, combinando estas herramientas, podríamos gestionar mejor la velocidad con la que se generan y procesan los datos.

2. Volumen: HDFS y MapReduce

Netflix genera grandes cantidades de información relacionada con las reproducciones, las búsquedas, los dispositivos utilizados y los hábitos de visualización.

Para gestionar este volumen, una herramienta útil sería HDFS (Hadoop Distributed File System), que permite almacenar archivos grandes repartidos entre diferentes servidores. De esta manera, no es necesario guardar toda la información en una única máquina y se puede ampliar la capacidad añadiendo más servidores.

También podemos utilizar MapReduce, que permite procesar grandes conjuntos de datos dividiendo el trabajo entre varios equipos.

Por ejemplo, si quisiéramos analizar las reproducciones de millones de usuarios durante varios meses para conocer las series más populares, podríamos almacenar los registros en HDFS y procesarlos mediante MapReduce.

3. ¿Por qué una base de datos relacional tradicional no sería suficiente?

Las bases de datos relacionales tradicionales, como MySQL, son muy útiles para almacenar información organizada en tablas y realizar consultas.

Sin embargo, si utilizáramos una única base de datos relacional convencional para almacenar y analizar todos los eventos generados por millones de usuarios de Netflix, podríamos encontrarnos con problemas de rendimiento y capacidad.

Además, algunos datos tienen formatos diferentes y se generan continuamente, lo que complica su gestión mediante una única base de datos tradicional.

En cambio, Hadoop permite repartir el almacenamiento y el procesamiento entre varios servidores, facilitando el trabajo con grandes cantidades de información.

Esto no significa que las bases de datos relacionales no puedan utilizarse en plataformas grandes, ya que existen soluciones distribuidas y sistemas capaces de escalar. La diferencia es que Hadoop está especialmente pensado para trabajar con grandes conjuntos de datos mediante procesamiento distribuido.

Conclusión

Consideramos que HDFS y MapReduce serían especialmente útiles para gestionar el volumen de datos de Netflix, mientras que YARN ayudaría a organizar los recursos de procesamiento.

Para la velocidad, sobre todo cuando necesitamos analizar información casi al instante, sería necesario utilizar herramientas adicionales como Apache Spark y Apache Kafka.

Por tanto, una arquitectura distribuida permitiría gestionar mejor estas dos necesidades que una única base de datos relacional tradicional.
